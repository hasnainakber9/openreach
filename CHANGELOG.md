# Changelog

All notable changes to OpenReach. Dates are when the work landed on its branch.

## Premium (unreleased, `premium` branch)

Every external service below is optional. Without keys, a built-in simulator stands in, so the app runs, builds and passes its tests offline. API keys are entered per workspace under **Settings → Integrations** and stored encrypted. Vendor integrations follow the vendors' public API docs and are tested against fakes, not the live services; see *Limitations* in the README.

### LinkedIn

- **Sender rotation:** one campaign can send from several LinkedIn accounts. New leads go to the account with the most room left today (or the one they're already connected to) and stay with it; each account keeps its own limits, hours, warm-up and delays. Leads an account hadn't contacted move to the others when it is paused, logged out or removed; leads already connected to it (or invited by it) wait for it instead. Results per sender.
- **A/B testing:** 2 to 5 variants for invitation notes, messages, InMails, emails and SMS, with stable per-lead assignment, per-variant stats, a *Leading* marker once the gap is statistically clear, and manual or automatic winners.
- **New lead sources:** import the people who reacted to or commented on a post, an event's attendees and a group's members, with live progress, cancelling, per-account daily import limits and deduplication.
- **InMail steps** (from the profile or from Sales Navigator) with a subject, their own daily limit and credit handling (open profiles are free); already-connected leads get a normal message instead.
- New branches: *has an open profile*, *email verified*, *reply is…*.
- **Sign in in a browser window:** a real account can be signed in by opening LinkedIn in a visible window on the account's own browser profile, where you sign in yourself (no password ever reaches OpenReach). Pasted `li_at` cookies often fail in OpenReach's browser with an endless redirect, because LinkedIn ties a session to the browser that created it; a session signed in this way is that browser's own. OpenReach stores it, closes the window and checks it; the window gives up after 10 minutes and can be cancelled from the card until you have signed in. Actions, imports and checks for the account wait while it is open, and it never opens while the account's browser is still closing. Real accounts can now be added without a cookie (they start as *Needs login*). Only offered where the server serves just its owner (billing off and `ALLOW_SIGNUP` off) and has a screen to show the window on (not Docker or a Linux server without a desktop), since the window opens on the server. A failed sign-in stops showing on the card once the account works again.
- **Browser-owned sessions stay current:** a session signed in in the window is never overwritten with the stored copy when the browser starts, and when LinkedIn renews the cookie the new value is stored, without restarting the browser. Pasted cookies are put in on every start as before. Session errors now point to *Sign in in a browser window*. Removing an account (or its workspace) now also closes its sign-in window and deletes its browser profile folder, which held its LinkedIn cookies.
- **LinkedIn's 2026 page layout:** the browser driver works with the profile layout LinkedIn started rolling out in 2026 (no `h1`, obfuscated class names, details as plain lines) and keeps the older layout's selectors as fallbacks. The name comes from the page title or the card's first heading; degree, headline, company (from its chip, never a school's) and location are read from the profile card by their order, using only what a person can see (hidden, transparent and screen-reader-only copies are left out; LinkedIn renders some lines and every action button twice, one copy hidden). Connect and Message work as links (Connect opens LinkedIn's invitation page when the click does nothing), *More* and its menu items are found in the new menu, Follow is taken from that menu, and messages are typed into the composer inside LinkedIn's shadow root. Likes use the new *Reaction button state* label; recent connections are read without list cards; 2026 inbox threads have no profile link at all (the name is a button), so the participant's link is read from the hovercard the name opens (best effort: that card was not captured live), and the name comes from the title bar when only you have written. A thread whose participant link can't be read is tied to a lead by name only when exactly one lead this account wrote to has that name and your message appears in the thread; otherwise it is stored without a lead. A link inside a message (a shared profile, a pasted URL) is never taken for the participant, and messages in a conversation bubble left open on the page are never read as the thread's. The driver waits up to 15 seconds for the profile card, and a profile whose card never appears is retried instead of failing the lead; when your own profile is slow to draw, the session check reads your name from the page title, or asks to try again later, instead of marking the account *Needs login*.
- **Safer LinkedIn actions:** actions are only taken from the profile's own card, never from *People you may know* beside it, and never from a control labelled with someone else's name. A message goes into the conversation bubble whose own profile card names the person, or else into the composer the click opened (told apart from ones already open, wherever LinkedIn puts it), never into a bubble left open with someone else even when it mentions the person; Send and close are taken from that same bubble. Invitation, contact-info and InMail dialogs no longer mistake an open message bubble (also a dialog) for theirs. Search imports leave out the mutual connections linked inside a result card.

### AI

- Anthropic (Claude) and any OpenAI-compatible API (OpenAI, OpenRouter, Ollama, LM Studio, ...).
- **Local models (Ollama, llama.cpp, LM Studio):** the OpenAI-compatible provider has three optional settings: a request timeout (60 s by default, up to 600 s for slow laptop CPUs), *Turn off model thinking* (`reasoning_effort: "none"` plus `chat_template_kwargs.enable_thinking: false`, so thinking models such as Qwen3.5 don't spend the 200-token classification budget reasoning) and *JSON mode for classification* (`response_format: json_object`). A server that refuses these optional parameters (400/422) is asked again with each on its own, then with neither, and what it refused is remembered; the host check runs before every attempt. Hosted installs cap the timeout at 60 s. `<think>` blocks left in answers are removed, an empty answer from a model that ran out of tokens thinking says how to fix it, a timeout says to raise the timeout, and *Test connection* checks the classification model name too (treating `name` and `name:latest` as the same). AI jobs now allow 11 minutes without progress (was 2 for classification, 5 for personalization). The README has an Ollama recipe for an 8 GB Windows laptop. Loopback stays allowed on self-hosted installs and refused on hosted ones.
- *Write with AI* drafts 1 to 5 versions of a step's text from a short brief; insert one or use them as A/B variants.
- `{{ai:name}}` variables: per-lead lines written in the background, cached, previewed on a real lead, with a fallback when writing fails or is slow (`AI_WAIT_MAX_MIN`).
- Reply classification (interested, meeting booked, question, not now, not interested, out of office, wrong person, unsubscribe, other) with inbox filters, manual correction and *Suggest reply*. Clear opt-outs go on a workspace-wide do-not-contact list.
- Campaigns can keep going after chosen kinds of reply (`REPLY_HOLD_MIN`).

### Email

- **Mailboxes** (Gmail, Microsoft 365 or any SMTP/IMAP server with app passwords): daily limits with a warm-up ramp, sending windows, random gaps, signatures, rotation across mailboxes, replies in the same thread.
- Unsubscribe link and one-click `List-Unsubscribe` headers on every campaign email; reply and bounce detection over IMAP (out-of-office and other automatic answers show in the thread but don't count as replies); DNS deliverability check (MX, SPF, DKIM, DMARC); optional open and click tracking, off by default.
- Email finding (Hunter, Apollo) and verification (Hunter, ZeroBounce, NeverBounce) in an ordered waterfall, per-lead email status and source, *Find email* step, automatic lookup after imports, Apollo company enrichment, monthly usage per provider.
- **Self-hosted verifier (AfterShip email-verifier, free and open source):** a new email verifier that calls [AfterShip email-verifier](https://github.com/AfterShip/email-verifier) (MIT) on your own machine at `GET {url}/v1/{email}/verification` (default `http://127.0.0.1:8080`, optional shared secret in `X-Verifier-Secret`). Bad syntax (including the stock server's plain-text reply) and disposable domains are invalid, `reachable: "no"` is invalid, a check that couldn't finish is unknown with its reason, catch-all is risky and an accepted mailbox valid. Costs no credits, sends at most one check a second per verifier, waits 60 s per check, and refuses loopback and private URLs on hosted installs (when saved and before every request). *Test connection* says whether the verifier's SMTP check is on. `docs/selfhosted/` has the Windows build steps (Go, tag v1.5.0, no Docker) and a replacement `cmd/apiserver/main.go` that turns the SMTP check on, sets the MAIL FROM and EHLO names, listens on 127.0.0.1 only, checks the secret, reports failed checks as JSON and runs two checks at a time. Mailbox checks need outbound port 25, which most home ISPs block.
- **Pattern finder (free, no key):** a new email finder that guesses addresses from the lead's name and company domain (`first.last`, `first`, `flast`, `firstlast`, `f.last` and 8 more patterns, most common first) with names normalised (accents, ß/Ø/Ł and similar letters, umlauts also as ae/oe/ue, apostrophes, titles, suffixes, nicknames, compound and hyphenated surnames, particles such as *van der*). Skips leads without a company domain, webmail and example domains, and disposable domains from the [mailchecker](https://github.com/FGRibreau/mailchecker) list (MIT, new npm dependency `mailchecker@6.0.21`), and domains without a mail server (MX lookup; a failed lookup is retried). It then asks the workspace's own email verifiers, in their order: a made-up address first, so a catch-all domain returns the top guess as *risky* with no more checks, otherwise the guesses in order until one is *valid*. A verifier that can't judge the domain (*unknown* for the made-up address) hands over to the next; one with a bad key or no credits is flagged and skipped; an outage is retried; rate limits wait. At most *Checks per lead* verifier checks (default 6, 2 to 20) and 3 minutes per lead. Catch-all answers (1 day; 30 minutes when the made-up address was only *risky*, which a greylisting server can cause) and confirmed patterns (30 days) are remembered per workspace and domain in memory. Without a verifier, or with verification of found addresses off for the run or the workspace (then no check is spent), it returns the most common guess as *unknown*, never *valid* or *risky*. The finder costs no credits; its verifier checks are logged and charged like any verification, and the waterfall doesn't check its answer a second time (new `verified` flag on a finder's result). Leads found this way show *Guessed from the name and company domain (Pattern finder)* as their source.
- **Company domain on import and edit:** CSV columns named *Company domain*, *Domain*, *Website*, *Company website* (and similar) fill the lead's company domain, and *Edit details* in the lead drawer can change it. A full URL keeps only its host (`https://www.Acme.com/about` → `acme.com`); anything that can't be a public website is left empty. Before this the domain only came from Apollo, so the free Pattern finder and Company website enricher had nothing to work with on leads without a work email.
- **DNS fallback:** MX and TXT lookups (Pattern finder, mailbox DNS check) that the system's DNS server refuses are asked again through `1.1.1.1` and `8.8.8.8`. On some Windows setups Node picks `127.0.0.1`, where nothing listens, which made every Pattern finder lookup fail and fall through to the paid finders. New settings `DNS_SERVERS` and `DNS_FALLBACK_SERVERS` (`none` turns the fallback off).
- A CSV import over 10,000 leads with *Find emails* on is looked up in several runs of up to 10,000, so no imported lead is left out.
- **Reply mode for servers nobody can reach:** emails only link to `PUBLIC_URL` (unsubscribe, open pixel, click redirects) when it is a public `https://` address; a `localhost`, private-IP, `.local` or plain `http://` address used to put dead unsubscribe links in real emails. A URL with a username or password, a query or a fragment doesn't count, and status messages show only its origin. Without a public address, a self-hosted server now sends from real mailboxes that have IMAP settings instead of refusing: the footer says *Just reply "unsubscribe" and I won't contact you again.* (or, with a *Reply-To* elsewhere, asks for an email to the sending address with that subject) and `List-Unsubscribe` is the `mailto:` alone. Servers that send other people's campaigns (billing on, or `ALLOW_SIGNUP=true`) still need a public `https://` `PUBLIC_URL` and say so in the mailbox status. With a link, the footer adds *or just reply "unsubscribe"*. Campaign warnings and the mailbox page say which mode is in use. Mailboxes stopped by an older version with *Set PUBLIC_URL...* go back to work at the next start when they may send.
- **Opt-out replies without AI:** an email whose subject is just "unsubscribe" (what the `mailto:` header sends, also from auto-responders) or a short reply (up to 200 characters without quotes and signature) that the keyword rules read as an unsubscribe ("remove me", "please remove my email", "never email me again", "why won't you stop emailing me?") puts the person on the do-not-contact list and stops them in every campaign as it arrives, labelled *Unsubscribe (unsubscribed by reply: ...)*. Quoted header blocks (also Outlook's and other languages'), our own footer, signatures and legal notices don't count as the person's words. "Don't unsubscribe me" (contractions now negate in the keyword rules), a reply that also says something positive, out-of-office text and longer messages are left to the classifier. Replies sent only as HTML are now read as text. When the AI fails for good, a sure *unsubscribe* or *not interested* from the keyword rules, read from the same short text, is applied (*keyword rules, AI unavailable*); other replies stay unclassified.
- **No email to unconfirmed guesses:** real mailboxes skip an address the Pattern finder guessed until a verifier calls it *valid* (or *risky* when the workspace accepts risky addresses), with *guessed address not confirmed by a verifier*. Other sources are unchanged.
- **Company website enricher (free, no key):** reads a company's homepage (and its About page when the homepage says little) for the name, description, logo, social profiles and, when published, founding year, size and address from meta tags, OpenGraph and schema.org JSON-LD, then Wikidata (by official website, P856) for industry, employees, founding year, headquarters and LinkedIn id. Honours `robots.txt`, identifies itself as `OpenReachBot`, keeps to about 1 request a second per site and to Wikidata, caches results, and guards every fetch (public hosts only, connections pinned to the checked addresses, default ports, no credentials, up to 4 checked redirects, 10 s per request and 30 s per site, 1 MB cap, linear-time parsing) on every installation. Ignores redirects to other sites, ISP and webmail domains, and email domains that plainly aren't the lead's company. Costs no credits, also on hosted plans, where each billing root gets 2,000 lookups a day and a share of the Wikidata rate. The lead drawer now also shows *Headquarters* and *About* company facts.

### Multichannel

- **Manual task** steps (call, LinkedIn by hand, email by hand, other) with due times, assignees, auto-skip, call outcomes and a **Tasks** page.
- **SMS and WhatsApp** steps through Twilio with daily limits and sending hours, replies through a signed webhook into the inbox, automatic STOP/START handling.

### CRM and pipeline

- Pipeline stages (editable), automatic forward-only stage moves, a drag-and-drop board with a keyboard-accessible *Move to* menu, owners, colored tags, notes and a lead timeline.
- One-way sync to **HubSpot** and **Pipedrive**: contacts with a field mapping, notes for replies and other events, optional deals at a chosen stage, a sync log with retries.
- **EspoCRM (self-hosted, free and open source, AGPL-3.0):** a new CRM provider for an [EspoCRM](https://github.com/espocrm/espocrm) you run yourself (on Windows with Laragon, PHP 8.3+ and MySQL/MariaDB, no Docker), with its address and an API user's key (`X-Api-Key`). Contacts are found by email (`where[0][type]=equals` on `emailAddress`), else by the mapped LinkedIn URL field, then updated (`PUT`, with emails and phones added to the contact's lists instead of replacing the primary one) or created. EspoCRM's 409 duplicate answer is read: a duplicate with the same email or LinkedIn URL is updated, and a namesake is created past with `X-Skip-Duplicate-Check`. Notes are stream posts (`type: Post`) on the contact; deals are opportunities with the required amount (0), `amountCurrency` (default USD) and close date (today + 30 days by default), an optional stage, and `contactId`/`contactsIds`. Errors carry EspoCRM's `X-Status-Reason` or the field that failed validation; 401 and 403 say what to fix on the API user and its role. *Test connection* (`GET /api/v1/App/user`) names the user and what its role may not do. At most 4 requests a second, 30 s per request; record links go to `{address}/#Contact/view/{id}`. Loopback and private addresses are refused on hosted installs (when saved and before every request; every request, writes included, connects only to the checked address). The field mapping now shows a per-CRM hint (EspoCRM custom fields start with `c`), `httpJson` takes an `errorDetail` hook for vendors that send their error reason in a header, and pinned requests (`pinnedFetch`) can now be writes (POST, PUT, PATCH, DELETE) with a string or byte body. The default mapping leaves out Title: EspoCRM stores a contact's title as their role at an Account, which the sync never sets, so it needs a custom field such as `cJobTitle`. A lead without a last name still creates a contact (named after its first name, email or "LinkedIn lead"), but that stand-in is never written over the last name of an existing contact found through EspoCRM's duplicate check.
- New webhook events: `lead.classified`, `lead.stage_changed`, `lead.enriched`.
- Bulk stage moves (the bulk edit, deleting a stage) run as a few statements and send one `leads.stage_changed` webhook with the count and lead ids, instead of one `lead.stage_changed` per lead.
- Lead CSV export: custom fields come out as `custom_<name>` columns (importing the file restores their names), and cells starting with `=`, `+`, `-` or `@` get a leading `'` so spreadsheets show them as text instead of running them.

### Teams, agencies and hosting

- People can belong to several workspaces and switch between them; invites by link or email (`SMTP_URL`, `MAIL_FROM`).
- **Agency mode:** client workspaces with an overview page, a read-only *Client* role, and white-label branding (product name, logo, color, support email, custom domain via `PUBLIC_URL`, `CUSTOM_DOMAINS` and `TRUST_PROXY`).
- **Plans and Stripe billing** for hosted installs (`STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `BILLING_PLANS` / `BILLING_PLANS_FILE`): Checkout, Customer Portal, signed webhooks and limits on accounts, mailboxes, seats, clients and monthly AI and enrichment credits. Off, and unlimited, without a key.
- Saved secrets stay with their server: changing an integration's base URL, or an SMTP host, port or user, needs the key or password again; only admins change SMTP settings and send test webhooks. On hosted installs, webhook URLs must be public hosts too (no redirects followed).
- After a downgrade or cancellation, only the oldest LinkedIn accounts and mailboxes the plan allows keep sending; the others still read replies, show why, and start again after an upgrade.
- **Postgres** as an optional database (`DATABASE_URL`), with leader election so several instances can share it while one runs the engine.
- A database-backed job queue for background work (`JOB_CONCURRENCY`).
- Changing your password signs you out everywhere else; a tab left on another workspace after a switch catches up instead of acting there.
